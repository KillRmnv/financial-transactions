# AI в проекте

**Чем пользовались.** CLI версия Opencode. В качестве причин выбора можно назвать выгодную подписку, отсутствие необходимости в vpn 
для большинства моделей, открытость исходного кода, расширяемость: сам агент поставляется в скромном сетапе, но благодаря большому коммюнити имеет множество расширений, 
которые остаются на выбор пользователя и как следствие уменьшает расход из-за отсутствия инструментов, которые были бы излишни.
## MCP-серверы

Три сервера, разнесённые по двум файлам конфигурации, потому что два разных агента читают два разных
формата:

| Сервер | Где | Зачем                                                                                                           |
| --- | --- |-----------------------------------------------------------------------------------------------------------------|
| **Context7** | `opencode.json` (в проекте) | в данном случае использование отследить сложно, ибо в opencode встроен базовый webfetch как нативный инструмент |
| **PostgreSQL** | `~/.config/opencode/opencode.jsonc` (личный) | SQL только на чтение по базе разработки, чтобы агент читал настоящую схему, а не угадывал имена колонок         |
| **GitHub** | `~/.config/opencode/opencode.jsonc` (личный) | задачи, pull request'ы и запуски CI — этим же публикуется репозиторий.Вот с CI самое удобное.                   |

`.mcp.json` в корне репозитория содержит те же три сервера в формате **Claude Code**. Он нужен
потому, что Claude Code — другой хост, читающий другой файл, а не по недосмотру: OpenCode игнорирует
его целиком, и это обнаружилось так: `opencode mcp list` отвечал *No MCP servers configured*.

## Где AI ошибся и как это заметили

В основном это можно разбить на две категории и соответственно два способа нахождения ошибок: ошибки в бизнес логике, т.е. в требованиях, что нее были задокументированы в тз,
но подразумеваются. Условно, для наполнения бд курсами валют агент предложил ленивое решение в виде миграции, т.е. хардкода.К тому же не предусматривает возможные точки отказа
по типу того, что внешний API резко по ошибке может вернуть список из неактивных валют, что спровоцировало бы выставление флага об активности валюты в false.
Ну и второй тип ошибок это уже сама реализация, где не рассматриваются edge cases. Отлавливается ручным либо автоматизированным тестированием, статическим тестированием кода глазными
яблоками. Из примеров можно привести отсутствие null проверок на сеттерах или неверный ответ от внешнего API(не в плане ошибки, а в плане семантики). Внешний API отдавал чепуху по одному из курсов


## Что написано руками

Модель была написана руками, поскольку она является основой для бизнес логики. От нее зависят репозитории,сервисы, DTO,Мапперы,контроллеры, нормализация бд, поэтому ее 
нужно крайне осмысленно задавать отсюда и вытекает необходимость самостоятельно задавать. Также реализовывались драфты алгоритмов с последюущей доработкой со стороны агента и 
различные правки пока бежит CI или генерируется код по типу пропущенных проверок(edge cases), выноса хардкода в конфигурацию, правка документации.
## Как применять скиллы

Скиллы лежат в `.agents/skills/`, симлинк `.claude/skills` указывает туда же, поэтому оба харнесса
их находят:

| Скилл | Про что |
| --- | --- |
| `changing-limit-behaviour` | правило флага, граница месяца, блокировка строки, автоматический лимит 1000 USD |
| `changing-swept-currencies` | `currency_pair`, цепочка поиска курса, переключатели в `scheduled_job` |
| `working-with-mcp` | два формата конфигурации агентов, read-only PostgreSQL-сервер, правила работы с git |

Каждый называет файлы, которые нужно прочитать, сценарий, который стоит запустить первым, и две
ошибки, которыми изменение чаще всего ломается. Запускайте `./scripts/ci.sh`, а не `mvn test`: он
сам закрепляет JDK и добавляет проверку формата.
