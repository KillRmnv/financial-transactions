# AI в проекте

**Чем пользовались.** OpenCode с загруженным контекстом репозитория: `AGENTS.md` хранит
конвенции, проверенное поведение правила флага и особенности инструментария, найденные по ходу.

## MCP-серверы

Три сервера, разнесённые по двум файлам конфигурации, потому что два разных агента читают два разных
формата:

| Сервер | Где | Зачем |
| --- | --- | --- |
| **Context7** | `opencode.json` (в проекте) | документация библиотек. Boot 4 переименовал столько координат Spring, что «артефакт, который я помню» регулярно ошибается, и посмотреть актуальный дешевле, чем выяснять это из ошибки компиляции |
| **PostgreSQL** | `~/.config/opencode/opencode.jsonc` (личный) | SQL только на чтение по базе разработки, чтобы агент читал настоящую схему, а не угадывал имена колонок |
| **GitHub** | `~/.config/opencode/opencode.jsonc` (личный) | задачи, pull request'ы и запуски CI — этим же публикуется репозиторий |

`.mcp.json` в корне репозитория содержит те же три сервера в формате **Claude Code**. Он нужен
потому, что Claude Code — другой хост, читающий другой файл, а не по недосмотру: OpenCode игнорирует
его целиком, и это обнаружилось так: `opencode mcp list` отвечал *No MCP servers configured*.

Две детали, стоившие времени, обе записаны в `AGENTS.md`:

- **`@crystaldba/postgres-mcp` больше нет на npm.** Реестр отвечает 404, а отказ выглядит как
  «сервер вышел с кодом 1», а не как отсутствующий пакет. Оба файла конфигурации называют
  `@contextflo/postgres-mcp`.
- **Удалённому GitHub-серверу нужен Copilot.** `https://api.githubcopilot.com/mcp/` отвечает 403 на
  обычный `gh` токен — который прекрасно работает против `api.github.com`. Настроен локальный
  Docker-образ, и он берёт тот же токен.

Токен GitHub никогда не пишется в файл: `config.fish` экспортирует его из `gh auth token`, оба файла
конфигурации ссылаются на `{env:GITHUB_PERSONAL_ACCESS_TOKEN}`. **Сервер должен видеть его в
окружении при старте**, иначе молча уходит в device-code flow, ждущий браузер. Подключение к
PostgreSQL несёт `default_transaction_read_only=on` и `statement_timeout=5000` по той же причине,
по которой защита живёт в конфигурации, а не в инструкциях: записываемое подключение агента к базе
разработки — это как пропадает таблица.

## Где AI ошибся и как это заметили

- Утверждал, что нулевой остаток считается превышением. Прогон правила по собственной таблице
  спецификации это опроверг: 2000 против лимита 2000 — это не `>`.
- Посчитал `999.99 + 0.01` как превышение лимита 1000. Feature с таблицей истинности это поймал:
  сумма ровно 1000.
- Добавил ошибку «лимит уже существует» при установке. Это противоречит спецификации, где второй
  лимит на ту же категорию — это и есть способ поднять лимит в случае 1. Сценарий выдал это, не сумев
  поднять лимит с 1000 до 2000.
- Реализовал создание лимита по умолчанию как «прочитал, потом записал», из-за чего две параллельные
  первые транзакции создают по лимиту. Это выдал сценарий конкурентных постов.
- **Гонка при записи курса**, найденная батчевым эндпоинтом: три транзакции в одной валюте делят один
  вызов провайдера и все три пишут одну строку. Наивный «прочитал, потом записал» давал
  `UnexpectedRollbackException` из коммита, не называвший ни ограничение, ни транзакцию.
- **Провайдер, проверенный на живом API, а не в заглушке.** Стаб WireMock отвечает на всё, что ему
  велено, поэтому два настоящих расхождения — отсутствие символа `KZT/USD` и отсутствие поля
  `previous_close` — держались до первой ручной проверки по живому ключу. Ни один сценарий их не видел.
- Ещё мелочи в тестах: feature, шаги которого не накапливали месячный итог, из-за чего третья
  транзакция дня считалась против начального остатка. Отказ проявился как сценарий с неверным флагом —
  ради этого слой Gherkin и нужен.

В каждом случае правка касалась сгенерированного кода, а не поймавшего теста. Сценарии написаны по
собственным числам спецификации, поэтому у них не было причин соглашаться с неверной реализацией.

## Что написано руками

Правило флага и его таблица истинности, SQL-миграции и решение хранить лимит на строке транзакции.
Это кодификация спецификации, а не повторение паттерна, поэтому они обдумывались, а не генерировались.

## Как применять скиллы

Скиллы лежат в `.agents/skills/`, симлинк `.claude/skills` указывает туда же, поэтому оба харнесса
их находят. Каждый закрывает одну область, а не пересказывает `AGENTS.md`:

| Скилл | Про что |
| --- | --- |
| `changing-limit-behaviour` | правило флага, граница месяца, блокировка строки, автоматический лимит 1000 USD |
| `changing-swept-currencies` | `currency_pair`, цепочка поиска курса, переключатели в `scheduled_job` |
| `working-with-mcp` | два формата конфигурации агентов, read-only PostgreSQL-сервер, правила работы с git |

Каждый называет файлы, которые нужно прочитать, сценарий, который стоит запустить первым, и две
ошибки, которыми изменение чаще всего ломается. Запускайте `./scripts/ci.sh`, а не `mvn test`: он
сам закрепляет JDK и добавляет проверку формата.
